# knowledge/ — 专用知识库（唯一事实源）

这里是整个项目**唯一的权威知识来源**。所有模型（Claude / GPT / DeepSeek / 以后的任何模型）都从这里读取知识；各模型空间 `models/<name>/` 只放适配层和候选知识，**不复制这里的内容**。

## 目录

| 路径 | 内容 | 变化频率 |
|---|---|---|
| `00_handbook.md` | 总纲：三条元原则、飞机拓扑、12 层速查、操作纪律。**任何模型先读它** | 低 |
| `INDEX.json` | 机器可读索引：领域 → 文件 → 来源技能 | 低 |
| `domains/KB_*.md` | 12 个领域知识文档（"事实 + 判据 + 踩过的坑 + 正确做法"） | 中 |
| `platform/` | 平台事实层：机型、传感器、固件、基线参数 | 低，需版本管理 |
| `gap-ledger/` | **sim-to-real 差异台账**：本项目最核心的资产 | 高 |
| `faults/` | 故障经验库：症状 → 根因 → 证据 → 修复 | 高 |
| `sources/` | 40 个原始技能 + 205 份配套文档，只读存档，用于追溯 | 不变 |

## 治理规则

### 1. 每条知识必须有来源
`gap-ledger/` 和 `faults/` 的每个条目必须写明证据：飞行日志编号、仿真 run 编号、或 `sources/` 中的原文位置。**没有证据的结论只能进 `models/<name>/inbox/`，不能进这里。**

### 2. 每条知识必须有适用范围
写明机型、固件版本、传感器型号、配置文件。范围之外的结论不可直接套用。

### 3. 状态机

```
候选(inbox) ──人工审核+eval通过──▶ 已验证 ──触发事件──▶ 待复验 ──复验通过──▶ 已验证
                                     │                       │
                                     └──被新观察推翻──▶ 已失效 ◀┘
```

**自动触发"待复验"的事件**：固件升级、换桨/换电机/换电池型号、换传感器、改 `MID360_Fly*.yaml` 或 SUPER/FUEL 关键参数、机载电脑换型。

### 4. 冲突裁决
新观察与旧条目冲突时：**以有实机证据的一方为准**；都只有仿真证据时，标为"冲突待验"，两条都保留并互相引用。

### 5. 汇报等级（沿用总纲 4.4）
任何条目的"状态"字段只能用：`已编写` / `离线通过` / `后端联通` / `实飞通过`。禁止把仿真结果写成实飞结论。

## 关于占位符

本仓库公开，所有口令、内网 IP、主机指纹、个人用户名已替换为占位符，例如 `<SSH_PASSWORD>`、`<NET_RC>.14`、`SHA256:<ONBOARD_HOSTKEY_FP>`。IP 只替换了网段、保留了主机号，因此"是否同网段"这类判据仍然成立。真实值见本地的 `.env`（不提交，模板为 `.env.example`）。

新增知识前请运行：

```bash
python tools/check_secrets.py .
```
