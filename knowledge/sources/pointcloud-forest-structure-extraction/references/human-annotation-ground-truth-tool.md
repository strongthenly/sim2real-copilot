# 真值靠【人工标注】：候选 → 标注器 → 冻结

> 起因：S0 那套「一个固定方法自动提取 + 人工抽查 50 棵」被用户核验推翻 ——
> **自动提取的真值只有约 50% 可靠**。用户的判断（原文）：
> *「任何『自动提取』的真值，在这种林下灌丛很密的场景里，本质上都是另一个检测器。
> 换一个参数、换一种方法，只是把问题挪了个地方。」*
> ⇒ **自动提取只产出【候选】；真值由【人】判定。**

---

## 一、为什么"自动 + 抽查"不够（反面教材）

S0 的做法是：1.3 m 单层切片 → 连通域 → 圆拟合 → 出 270 棵 → 出两张核对图 → 抽查。

**用户把两块查漏区域在 0.8 / 1.3 / 2.0 m 三个高度分别切片后逐棵看，结论：**

```
真树的样子：三个高度【同一位置】都有一个干净的小圆环（弧可缺，但圆心/半径一致）
v1 的问题 ：区域2（真值 37 根）能对上干净树干的只有约一半；
            52/47/7/125/85/128/163/174/36 这类都是【较大的圆套在一片散乱的枝叶或灌丛点上】，
            三个高度都没有对应的圆环
            另外还【漏掉了至少 4~5 根明显的圆环】
            id165 圈的是一个矩形轮廓 —— 大概是人造物
```

### ⚠️⚠️ 由此暴露的【体检设计】教训（比结论本身更值钱）

我那份自动体检做了三项：**A 近邻对 <0.6 m（疑分叉）/ B 半径越界 / C 高度层缺失**。
结果 **A = 0 对** —— 我当时把它当成"没问题"的证据 ✗

> **用户的纠正**：*「近邻对为 0，并不能说明没问题，因为误判的主要来源是灌丛和枝叶，不是分叉。」*
> *「体检里标出的 64 棵只是冰山一角。」*

**🔑 教训：自动体检必须覆盖【实际占主导】的失效模式。**
本次占主导的是"**大圆套在散乱枝叶/灌丛上**"，而 A/B/C 三项**一个都没覆盖它** ✗。
**⇒ 设计体检项时，先列出所有可能失效模式并排序，不要只挑"容易自动化的"那几项。**
**⇒ 而"大圆套在枝叶上"这种空间形态问题，本质上只能靠【多高度目视对比】发现。**

### 🔑 决定性检查：**多高度并排目视对比**

这是用户自己发明、我此前没做的关键动作 —— **把同一位置在 0.8 / 1.3 / 2.0 m 分别切片并排画出来**：

```
真树  ⇒ 三个高度同一位置都有干净小圆环
枝叶堆 ⇒ 三个高度都没有对应的圆环（或只有一处有）
```

**单层切片看不出的问题，三层并排一眼就看出来** ✓
⇒ **这个视图必须成为标注器的主界面**（不是可选功能）。

## 二、标注工作流（本次实现，可直接复用）

```
① 候选 = 两个【结构不同】的检测器的并集，去重
     v1 单层切片 270  ∪  RANSAC 圆柱 269  →  0.60 m 合并去重  →  428 个
     ★ 并集是为了【少漏】；候选不是真值，宁多勿漏

② 评估区域 = 只标【点云足够密】的地方
     按 LAS 点密度选 10×10 m 块（密度 ≥ 中位数），取到 ~150 个候选
     实测 5 块 → 170 个候选，预计标注 20~30 分钟
     ★ 理由：LAS 没扫到的地方在仿真里会被当空地、射线直接穿过去 ⇒ 可见性偏乐观

③ 每个候选一张【三高度并排小图】0.8 / 1.3 / 2.0 m
     红圈 = 该候选的拟合圆；灰圈 = 邻近其他候选（供参考，别被干扰）
     实测 170 张共 1.7 MB（平均 11 KB）⇒ 秒开

④ 键盘判定： y = 真树 / n = 不是 / ? = 不确定 / ←→ 翻页 / u 撤销 / g 跳到未标注
     标注自动存 localStorage；**必须给显式的"导出"按钮**（换机/清缓存会丢）

⑤ 区域模式补漏：满幅 clickmap 上【点一下】补一棵漏掉的树
     分区大图（三高度，红圈=候选）作参考 + 独立 clickmap 作精确点选

⑥ 冻结为 anchor v2：记录【标注人 / 日期 / 标注工具 MD5 / 候选生成脚本 MD5】
     对 "?" 做【敏感性分析】（算作树 / 不算作树，结论是否变化）
     此后所有实验（S3/S4）都用 v2，不准再改；再发现问题就另起 v3 并说明差异
```

## 三、纳入标准必须【事先写死】

**★ 不看结果再调**（否则又是在坏尺子上调参）：

> **在 0.8 m / 1.3 m / 2.0 m 三个高度中，至少两个能在同一位置看到"圆环或清晰的弧"，
> 且直径不小于约 6 cm（r ≥ 0.03 m）。**

判定要点写进工具界面：
- **真树**：三个高度同一位置都有**干净的小圆环**（弧可缺，但圆心一致、半径一致）
- **不是树**：较大的圆套在**一片散乱的枝叶/灌丛点**上，且三个高度**都没有对应的圆环**
- **不确定**：只在一个高度看到弧 / 点数太少 ⇒ 记 `?`，事后单独讨论

## 四、工程实现要点（踩过的坑）

### 1. 单文件 HTML 标注器：**用 `manifest.js` 而不是 `fetch('manifest.json')`**
浏览器在 `file://` 下**禁止 `fetch` 本地文件**（origin=null）✗。
```html
<script src="manifest.js"></script>          <!-- ✅ file:// 可用 -->
<script>/* window.MANIFEST = {...} */</script>
```
图片用**相对路径 `<img src="v2_img/c0000.png">`** ✓（`file://` 下正常）。
⇒ 整个工具是"一个 HTML + 一个 manifest.js + 图片目录"，**双击即用、不需要起服务** ✓

### 2. 区域点选要精确映射 ⇒ 必须渲染【满幅无边框】的 clickmap
普通 matplotlib 图有边距/坐标轴，**屏幕坐标无法线性映射回世界坐标** ✗
```python
fig = plt.figure(figsize=(6, 6), dpi=110)
ax  = fig.add_axes([0, 0, 1, 1])        # ★ 满幅，无边距
ax.set_xlim(x0, x0 + SIZE); ax.set_ylim(y0, y0 + SIZE)
ax.set_aspect("equal")                   # ★ 数据范围是正方形 + 图幅正方形 ⇒ 零内边距
for sp in ax.spines.values(): sp.set_visible(False)
ax.set_xticks([]); ax.set_yticks([])
```
⇒ 浏览器里 `wx = x0 + (clientX - rect.left) * SIZE / rect.width` **无误差** ✓
再叠一层 **每 2 m 的坐标网格**（标数字）供人读位置 ✓

### 3. `manifest.js` 里要带**冻结凭据**，导出时一并落盘
`script_md5` / `criteria`(纳入标准原文) / `regions` / 每个候选的 `x,y,r,src`。
导出得到 `anchor_v2_labels.csv` + `anchor_v2_labels_meta.json`（含标注人、时间、MD5）。

### 4. Windows 启动器 `.cmd`
- **内容必须纯 ASCII**（不能出现中文路径/中文文字）
- **写完后查 UTF-8 BOM 并去掉**，否则 cmd 按 ANSI 读会解析崩：
```powershell
$b=[System.IO.File]::ReadAllBytes($cmd)
if($b.Length -ge 3 -and $b[0] -eq 0xEF -and $b[1] -eq 0xBB -and $b[2] -eq 0xBF){
  [System.IO.File]::WriteAllBytes($cmd, $b[3..($b.Length-1)]) }
```
- matplotlib 画中文要**先设字体**：`rcParams["font.sans-serif"]=["Microsoft YaHei","SimHei"]`
  （不设就只有一堆 `Glyph xxxxx missing from font(s) DejaVu Sans` 警告、中文全变方框）

### 5. 候选小图渲染的性能
按高度层各建一个 `cKDTree`（0.05 m 体素抽稀后全点云），逐候选 `query_ball_point(±1.1 m)`。
实测 **170 张 × 3 层 = 9 秒** ✓ 不用做任何特殊优化。

## 五、论文里怎么写这件事

**"自动提取的真值只有约 50% 可靠"本身就是可写的素材** —— 作为**采用人工校核真值的依据**：

| 方法 | 树干数 | 半径中位 | 人工核验 |
|---|---|---|---|
| 单层切片（1.3 m）| 270 | 0.093 m | **约 50% 可靠** ✗ 大量圆套在灌丛/枝叶上 |
| 自动体检（近邻对/半径/高度层）| 标记 64 棵 | — | **只覆盖分叉/半径/缺层，漏掉主导失效模式** ✗ |
| RANSAC 圆柱 | 269 | 0.40 m | 与上面合并作**候选**，不作真值 |

**必须写明的局限**：
1. **人工判定有主观性** ⇒ 报告 `?` 的数量，并对 `?` 做敏感性分析
2. **候选来自两个自动方法的并集** ⇒ 两者的**共同漏检**即候选的漏检（靠区域模式补漏缓解，无法保证补全）
3. **只标了点云足够密的若干块** ⇒ 结论适用范围限于此类林分，不能外推到稀疏区
4. **真值冻结后不随检测改进而更新** —— 这正是"独立参照"的意义
