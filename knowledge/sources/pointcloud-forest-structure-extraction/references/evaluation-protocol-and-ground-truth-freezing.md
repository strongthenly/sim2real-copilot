# 评估协议与真值冻结（本课题的尺子怎么做才算数）

> 这份文件是**用户亲自给出的 7 条实验设计要求** + 可直接重跑的冻结协议。
> 起因：本次会话用 **5 种结构完全不同的算法**改在线树干检测，精度**全都卡在 ~10%**，白费 5 轮 ——
> 根因是评估锚（CHM 峰值法的**树冠中心**）只覆盖真实树干的约 1/5。**尺子坏了，量什么都白量。**

## 一、用户的 7 条硬要求（逐条照做，不要自己发明）

1. **真值必须独立于检测器，且一次生成、人工抽查、之后冻结**
   - 若"有效树"的定义是"离某个**检测结果** 0.30 m 以内的点云位置"⇒ 还是**自己考自己** ✗
   - 正确：在**完整 LAS** 上用**一个固定方法**提树干 → **人工抽查约 50 棵** → **冻结** → 之后所有实验都用同一份，**调检测或调规划都不许改它**
   - 门槛（如"≥20 点"）**偏向采集时扫得清楚的树**，被遮挡的树点少会被排除 → 真值集合里全是"容易扫的树"
     ⇒ **要么在论文里写明这一偏置，要么把门槛调低再人工核查**
2. **覆盖率的分母 = 「可覆盖的扇区」，不是固定 12**
   - 仿真是从 LAS 取点，而 LAS 是沿一条手持路线采的，很多树干只有一两面有点
   - 某扇区在 LAS 里没有点 ⇒ 仿真里永远扫不到 ⇒ **指标带一个随树而变的隐形上限，规划做得再好也显示不出来**
   - 定义：`覆盖率 = 已扫到的扇区 ÷ LAS 里有点的扇区`
   - ★ 这一条**对论文可信度最关键**
3. **覆盖率要从「飞行中实际扫到的点」算，不能用规划器自己记录的扇区计数**
   - 评估时：拿仿真飞行累积的扫描点，按**冻结真值树**逐棵重算扇区覆盖
   - 检测器好不好**另外单独报**它相对真值的**准确率/召回率**
   - ⇒ 这样"规划效果"与"检测效果"才能**分开归因**
4. **预算不能按【视点数】算**
   - 实测：`gain` 模式比 `nearest` **多飞 15% 路程**（149.5 m vs 129.9 m）—— 它偏好更远的视点
   - 按视点数比较**对它不公平**，也说明不了问题
   - 正确：在**同样的飞行距离或飞行时间**下比较，画"**真树达标数随路程变化**"的曲线，再取**曲线下面积(AUC)** 对比
5. **每个配置只跑一次得不出结论**
   - 即使仿真是确定性的，**换一个起飞点结果也可能反过来**
   - 做法：固定 **5~10 个起飞点**，每个配置在每个起点都跑一遍，**按起飞点做配对比较**，报告**均值和置信区间**
   - 规模估算：一轮 3 分钟 ⇒ 5 起点 × 6 配置 ≈ **1.5 小时**，完全可以接受
6. **不要先直接改检测阈值（如 `MIN_INLIERS 40 → 120`）**
   - 在真值冻结之前改 = **又一次"在坏尺子上调参"**
   - 而且**只扫到一侧的树、离得较远的树点本来就少**，门槛一提就把它们直接过滤掉 ——
     可**这些树恰恰最需要规划器去补扫** ✗
   - 改为**两级判据**：
     - **候选树**：低门槛
     - **确认树**：再通过**多层高度的竖直一致性检验**
     - **规划器的一个任务，就是飞过去把候选树确认掉**（← 这是"以物体覆盖率为目标"的自然延伸，对论文是**加分项**）
   - 阈值用**检出准确率/召回率的权衡曲线(PR 曲线)** 来选，**不要凭感觉定一个数**
7. **消融实验用 leave-one-out，不要"逐项往上叠加"**
   - 叠加法的结果**受叠加顺序影响**
   - 三组对照都做：**baseline** / **full（全部创新点）** / **full 分别去掉某一项**

## 二、冻结协议（可重跑，实测一次约 2 分钟含 LAS 全读）

**方法（林业 DBH 标准做法，参数全部写死、不做调优）**
```
① 地面：2 m 格取 z 的 5% 分位 + 一轮跨格稳健化（高出 3x3 邻域中位 >3 m 的格判为非地面格，用邻域中位替代）
        —— 自包含实现，刻意不复用被评估系统的地面代码
② 离地 1.25~1.35 m 单层水平切片
③ 投影 XY → 0.05 m 格 → 8 连通域
④ 每块圆拟合；保留 半径 0.03~0.80 m、点数 ≥15、拟合 RMS ≤0.10
⑤ 中心距 <0.80 m 的合并
⑥ 记录（**只用于论文分组报告，不用于筛除**）：
     n_las       = LAS 在水平 0.40 m 内、离地 1.0~2.2 m 的体素数
     sectors_las = 该范围内【12 个方位扇区里哪些有点】的位串  ← 第 2 条要求的分母
```
**输出**：`anchor_trunk_FROZEN_v1.csv`（id,x,y,r,ground_z,n_las,n_sectors_las,sectors_las,**script_md5**）
+ 两张核对图（总览俯视 / 抽样 50 棵的切片点云 + 拟合圆）+ **脚本 MD5 作冻结凭据**

**实测结果（4.59 ha 松林，7600 万点手持扫描）**
```
树干总数 270 根   （CHM 树冠法只认 230 棵 → 独立方法多找出 40 根）
n_las        中位 391  10% 175  90% 858  最大 1580  **为 0 的：0 根**
可覆盖扇区数  中位 12   均值 11.0   ≤2 个的仅 3 根   =12 个的 176 根
半径 r       中位 0.093 m  10% 0.052  90% 0.163
```

**⭐ 意外收获：可覆盖扇区中位 = 12** → 高密度手持扫描绕行密集 ⇒ **"隐形上限"问题比预期小**
（但仍**必须**按可覆盖扇区做分母：只有 3 根 ≤2 个扇区的树会严重失真，且论文里必须说明口径）

**仍然成立的部分（机制，要记住）**：**RANSAC 的目标函数 = 最大化内点数**
⇒ 圆越大圈住的点越多 ⇒ 拟合器**天然偏向大圆**。任何"最大化内点/覆盖率"的拟合器都有这个偏置。

**🔑 真正该记住的是这条纪律**：
> **任何"自动提取"的真值，在林下灌丛密的场景里，本质上都是【另一个检测器】。
> 换一个参数、换一种方法，只是把问题挪了个地方。**
> ⇒ 自动提取**只能产出候选**；真值须**人工标注**（见 `human-annotation-ground-truth-tool.md`）
> ⇒ 真值经人工核验之前，**不要从它推出任何"X 是 Y 的 N 倍"类结论**

> 在坏尺子（CHM 树冠中心）下这个问题看不出来 —— 但**修好自动尺子也看不出来**，
> 因为**自动尺子自己有 ~50% 的错**。必须跳到"人标注"那一档。

## 五、评审这 7 条时的自查清单

交付任何"改进有效"的结论前，逐条问：

```
[ ] 真值是否独立于被测系统？是否冻结（有 MD5 凭据）？是否人工抽查过？
[ ] 覆盖率分母是"可覆盖扇区"还是固定总数？
[ ] 覆盖率是来自"实际扫描点"还是"系统自报的计数器"？
[ ] 两个配置是否在【等飞行距离/时间】下比较？比的是 AUC 还是终点值？
[ ] 跑了几个起点？有没有配对比较 + 置信区间？
[ ] 有没有在冻结真值之前改过检测阈值？
[ ] 消融是 leave-one-out 还是逐项叠加？
```

**任何一条不过，结论都还不成立** —— 本次两轮 A/B 从 `+22 棵` 翻到 `−9 棵`，就是这几条没守住的结果。

## 六、⭐⭐ 换真值之前：先用【合成数据】校准评估器（用户亲授，必做）

> 用户原话：*"S1、S2 写的都是评估代码，真值只是它的输入文件。所以这部分可以提前写，还能提前验证：
> **先用合成数据校准尺子** …… 评估器过了这一关，之后换成 LAS 真值时，出了问题就只可能在真值本身，归因很干净。"*

**为什么这一步省不掉**：评估器是纯代码，真值是数据。**两者一起上线时出了错分不清是谁** ✗。
先让评估器在**答案已知**的场景上过关，就把"评估器 bug"这个变量彻底消掉。
**这与"S0 冻结真值"是同一条纪律的两半：先让尺子自证，再让尺子去量东西。**

### 做法：造一片【答案事先手算好】的合成树林

可直接复制改造的骨架：**`templates/evaluator_selftest_synthetic.py`**

```
合成 N 棵树，位置/半径/每个扇区"能不能扫到"全部由你自己写死
  → 由此【手算】出期望指标（平均覆盖率 / 达标数 / 达标率 / PR）
  → 把三种场景喂进评估器：【全扫到】【只扫一半】【一棵都没扫】
  → 断言输出 == 手算值，打印 PASS/FAIL 表，**exit code 非零即失败**（可进 CI / canary）
```

### 必须包含的断言（每条对应一个真实口径约定）

| 断言 | 守住什么 |
|---|---|
| **只有 8 个可覆盖扇区、且全被扫到 ⇒ 覆盖率必须是 1.0，不是 8/12=0.667** | ★**分母用"可覆盖扇区"而非固定 12** —— 这条断言就是那个修正的**回归测试** |
| 可覆盖扇区 < 阈值（如 4）的树 ⇒ 进"单独报告"组，**不进主指标** | 少扇区的树覆盖率一次跳 ≥25%，太粗 |
| 可覆盖扇区 = 0 的树 ⇒ 覆盖率 `nan`，**从主指标剔除**而非算 0 | 否则系统性拉低平均值 |
| τ 从 0.5 走到 1.0 ⇒ 达标率**单调不增** | τ 曲线自洽 |
| 检测与真值完全重合 ⇒ P=R=1.0；再加 k 个远距离误检 ⇒ P 按比例下降 | 匹配规则（一对一 + 阈值 `max(0.3m, 2r)`）|
| 检测整体偏移**超过**匹配阈值 ⇒ 匹配数必须是 **0** | 证明阈值真在起作用（不是"全都匹配上"）|

### ⚠️⚠️ 合成夹具自身的两个坑（实测踩到，**都不是评估器的错**）

1. **夹具几何要避开"意外对齐"**：本次合成树沿 y 轴**间隔正好 5 m**，我又把检测整体沿 y 偏移 **5.0 m**
   ⇒ 每棵树偏移后**正好落到隔壁那棵树的位置上** ⇒ 匹配数 4（我断言期望 0 ✗）。
   **评估器是对的，夹具设计错了。** ⇒ **偏移量与间距要用互不成比例的数**（如偏移 2.0 m 而间距 5 m），
   或把夹具改成非网格排布。
2. **期望值要按夹具的【实际形状】算**：本次写成 `np.vstack([truth] + [truth+offset]*5)`
   ⇒ 真值 m 行 × 5 份 = **5m 个**误检（不是 5 个）⇒ P 的实际期望是 `m/(m+5m)`，我却填了 `m/(2m)` ✗。
   ⇒ **断言失败时先重算期望值，再怀疑评估器。**

**🔑 判据：合成校准的 FAIL 有 ~90% 是"你的期望算错了"，不是"评估器写错了"。**
本次 18 条断言里 2 条 FAIL，**两条都是我的期望值错**，评估器一次全对 ✓
**这正是这一步的价值 —— 它逼你把口径想清楚，而不是把 bug 带到真值上去。**

## 七、S0 体检报告协议：**只标记，绝不自动删除**

> ★★ 核心纪律：**自动删除可疑项 = 让真值重新与被测系统耦合** ✗
> 体检报告的唯一目的是**给人工核查标记重点**；最终剔除由人决定。
> 剔除动作一旦做出，就当作 **anchor v2 重新冻结**，并记录**新的脚本 MD5**。

### 三项自动体检（全部只打标记）

| 项 | 判据 | 意图 |
|---|---|---|
| **A 近邻对** | 两棵树中心距 < **0.6 m** | 可能**分叉被算成两根** |
| **B 半径越界** | `r < 0.05` 或 `r > 0.40` m | 只拟合到一小段弧 / 拟合失败 |
| **C 高度层缺失** | 离地 **0.8 m 与 2.0 m** 对应位置**都没有点** | 可能只是**横枝或灌木顶**，不是整根树干 |

**C 最有价值** —— 它直接命中"单层切片会切到低矮枝条"这个偏置。实测（270 棵树）：

```
A 近邻对 <0.6 m : 0 对            ← 好消息：1.3m 切片 + MERGE_R=0.8m 没有把分叉算成两根 ✓
B 半径越界      : 23 棵（全是 r<0.05，无一 r>0.40）
C 0.8m 处无点   :  4 棵
  2.0m 处无点   : 42 棵（15.6%）  ← 近 1/6 的"树干"在 2 m 高度没有回波
  两处都无点    :  3 棵           ← 极可能是枝条，必须人工判
合计被标记(去重): 64 棵 / 270 = 23.7%
```

**读 C 的注意**：`2.0 m 处无点`有**两种**解释，**不能自动判死**：
- 真是枝条/灌木 ✗ —— 或 —— 只是 2.0 m 处**被遮挡** ✓
⇒ 要和 `n_las` 一起看：**`n_las` 很大却 `cnt_2.0m=0`** 才最可疑
（实测 id 55：`n_las=852, sec=12, cnt_0.8m=55, cnt_2.0m=0` —— 点很多却全挤在一个高度层）。

### 人工作业材料必须一起导出（否则"抽查"落不了地）

1. **分层抽样图**（**不是纯随机** ✗）：并集取
   —— 按 `n_las` 降序均匀取 20 棵 + 半径最小 8 棵 + 半径最大 8 棵 + 可覆盖扇区最少 8 棵
   + **所有被标记的树**
   ⇒ 保证**尾部极端值一定被看到**（实测并集 57 棵）
2. **逐棵局部点云 `.ply`**（挑半径接近中位的 5 棵，**文件名带拟合 r**）
   ⇒ 用户在 CloudCompare 里**手动量半径**，对照中位 0.093 m
3. **若干 10×10 m 区域 `.ply`** + 该区域真值表内的树干数
   ⇒ 用户**人工数树干**，查真值**有没有漏**

**⚠️ 抽查的验证能力是有边界的，必须对用户明说**：
- 抽查 50 棵 ⇒ 只能证明"**真值里的树是真的**"
- **证明"没有漏掉的树"需要另一套动作**：随机选 3~5 块 10×10 m，**人工在点云里数树干**再对照
- 实测 3 块区域真值表内树干数 = **5 / 36 / 13** ⇒ 顺带暴露**林分密度极不均匀**（区域间点数差 7 倍）
- 全部体检产物一律加 **`PROVISIONAL_` 前缀**，冻结前**不作为论文数字**
