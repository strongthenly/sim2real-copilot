# 树干覆盖度自检（圆柱面 (θ,z) 展开法）+ 上游 ground 填充值陷阱

## 一、算法：把树干当圆柱面，覆盖度就变成可精确量化的东西

树干是圆柱面 → 参数化成 `(θ, z) ∈ [0,2π) × [z0,z1]`，离散成 `36 × 20 = 720 格/树`。

```
某格"已覆盖" ⇔ 该格内有回波点（可加阈值：>=N 点才算）
覆盖率 = 已覆盖格 / 720
缺失部分 = 未覆盖的 (θ,z) 格 → 直接告诉规划器"该从哪个方向、哪个高度去补扫"
```

**为什么这比 frontier exploration 好**：frontier 是"未知空间格"，保证的是**体积覆盖**；
这个保证的是**指定结构的表面完备性**，指标明确（trunk completeness %），可做论文的量化对比。

**实现要点**（`_coverage_check.py`，Windows Python + numpy/scipy/matplotlib，不依赖 ROS）：
- `scipy.spatial.cKDTree` 建树心 2D KD 树 → 每点 `query(k=1, distance_upper_bound=r_max)` 找最近树
  → 76M 点点云 **11 秒**跑完（比逐树筛点快几个数量级）
- 逐 chunk 累积 `np.add.at(cov3d, (tree_idx, θbin, zbin), 1)` → 内存 O(树数×720) 极小
- 树干半径用**径向直方图峰值**估计（0.04~0.90 m 内取峰），比对没测到的树回落到经验值
- 支持 LAS(chunked) 和 PCD(ascii/binary) → 同一工具先算手持 LAS（参考上限），后算无人机 PCD

## 二、⚠️⚠️ 上游陷阱：**"无数据的格"被填成有限值 → 下游全错**

`ground_1m.npy`（1m 逐格地面）里 **75% 的格被填成 `-8.80`**（一个有限值，不是 NaN）：

```
ground_1m.npy: 46487 格, np.isnan 数 = 0    ← 致命的"零 NaN"
  -8.80 出现 31,178 次 (67%)，加上 -8.8x 共 34,840 次 (75%)
  真正有数据的格只有 11,735 = 25.2%
```

**后果链**（全部真实发生过）：
```
"只有树冠、无地面回波"的格 → ground 填成 -8.80
  → CHM = grid_max - ground 虚高（实测 CHM 达 46~49 m）
  → 树高被算成 25~49 m，被 cap 到 35 → 出现一堆"树高=35.0"的假高树
  → 树干 z 窗口 [地面+0.1, 地面+12] 挂在错误高度
  → 50% 的树"零树干点"（覆盖度看起来惨不忍睹，其实是地面错了）
```

**⚠️ 判别要点**：
- **看 `np.isnan(x).sum() == 0` 就要警惕** —— "零 NaN"往往意味着"用有限值做了填充"
- 用 `np.unique(np.round(v,2), return_counts=True)` 找**出现次数异常多的值** → 那就是哨兵值
- 拿**点云实测地面（±4m 内 z 的低分位）**做裁判，逐格对比两个候选 ground 的误差

**修 ground 的正确姿势**（不要用邻域中位判据 —— 它会再次被填充值污染）：
```
base = grid_min            # 每格最低点（不用 ground_1m）
ground = 对 base 做渐进形态学/滑动低分位（求"地面下包络"）
         # 树冠格的 grid_min 显著高于邻域 → 自然被下包络排除
再用最近邻把无数据格填上
⚠️ 做邻域统计时【绝不能把无数据格填成 1e6 之类的哨兵】—— 会污染中位数（我踩过）
```

## 三、其它坑
- `np.isnan` / `isfinite` 检查只看**一个**数组不够：`grid_max` 用 `-inf` 作哨兵、`ground_1m` 用 `-8.80` 作哨兵，两者判据不同
- 两个看似同源的中间产物可能**完全不同**：`ground.npy` vs `ground_1m.npy` 逐格全不同、最大差 25 m
- mask 之后要**同步 mask 所有派生数组**（我漏了 `zmax` → 广播形状错）
- 把字符串列（如 `kind`）塞进 `np.array(rows, dtype=float)` 会炸
