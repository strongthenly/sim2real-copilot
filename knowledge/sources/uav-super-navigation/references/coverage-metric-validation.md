# 覆盖度指标的**验证**：判断"报出来的覆盖率"可不可信

（讲**怎么验证一个覆盖率数字是真的**。怎么**算**树干覆盖度见点云侧 `pointcloud-to-ue4-airsim-world/references/trunk-coverage-selfcheck.md` 的 (θ,z) 展开法；本篇承接 tree_scan 的在线覆盖率。）

## 触发
- 用户问"扫描到的树覆盖完整吗"
- 拿到一个**在线自报**的覆盖率（例：`tree_scan` 报平均 67%）要判断真假
- 要拿覆盖率当论文指标 / 验收标准

## 铁律：任何自报覆盖率，都要在**真值数据**上用**完全相同的判据**复算一遍

只"看数字合不合理"是判断不出来的。必须三方对比：

| 口径 | 数据源 | 作用 |
|---|---|---|
| **在线自报** | 系统自己跑出来的（在线点云 + 它自己的判据） | 被验证对象 |
| **粗口径复算** | **真值点云**（手持 LAS 等） | **完全复刻**它的判据 ⇒ 控制变量 |
| **细口径复算** | 同上真值点云 | 更细判据（如 36×20=720 格）⇒ 真实水平 |

**复刻要点**：扇区数、体素尺寸、高度带、每格阈值**全部照抄**，只换数据源。
否则口径差异会淹没数据差异，什么都证明不了。

**再补一层自洽性检查**：粗口径与细口径应**彼此高度相关**（本次 r=0.885 ✓）。
若粗/细自洽、但都与在线不一致 ⇒ **问题出在在线数字**，不在你的复算 ✓ 很强的定位信号。

## ⭐⭐ 冒烟枪判据：物理上不相交的两组，报出同一个覆盖率

本次最有说服力的证据 —— 按"真值里树干带内**有没有点**"把树分成两组：

```
有树干点的 156 棵： 在线报 0.693 / 真值复算 0.613   ← 吻合 ✓
无树干点的 324 棵： 在线报 0.666 / 真值复算 0.000   ← 虚高 ✗✗
                   ↑ 两组报的几乎一样
```
**两组覆盖率的来源物完全不同，却报出同一个数 ⇒ 该指标不是由它声称的东西决定的** ✓ 铁证 ✓

同族信号（任一出现就去查）：
- 覆盖率**千篇一律卡在同一个值**（如全 `0.67 ≈ 8/12`）
- `covered_bins` 几乎**全 1**（绕一圈全满足），而真值里该树压根没有树干点
- 与"真值有/无"完全不相关（本次在线 vs 复算 **r=0.055**）

## ⭐ 虚高的典型机制（本次定位到的）

在线判据：`12 扇区 × 每扇区 ≥2 个 0.05 m 体素 × 离地 1.0~2.2 m`
但"离地"用的是 `ground_at()` = **2 m 网格最低点** →

```
密林里 2m 网格最低点偏高 → \"离地 1.0~2.2 m\"的绝对高度带落到【树冠】上
  → 树冠点/枝叶体素满足判据 → 被算作\"树干已覆盖\" → 虚高 ✗
```
**判据：覆盖率异常高 + 覆盖率与"树干带实测点数"不相关 ⇒ 先查高度带的参考地面是怎么来的。**

## 指标设计教训（拿去改指标）

| 问题 | 修法 |
|---|---|
| 扇区太少（12 = 30°/格）失去分辨力，树冠绕一圈自然全满足 | 扇区数 **≥36**（10°/格） |
| "某扇区有 ≥2 个体素" 太松 | 加**每格点数阈值**，必要时加**入射角**约束 |
| "检测成树" 与 "算覆盖" 两套口径不自洽 | 让两者用**同一个高度带 / 同一个地面基准** |
| 检测把灌木/树冠当树干（本次 480 棵里只有 156 棵真有树干） | 加**竖直性/高径比**约束过滤 |

## ⚠️ 比较两个树表之前：先确认坐标系/量纲可比

本次我的合成树表 `x −97.7~116.3` vs 在线 `x −44.7~45.4` ✗ 看着像坐标系不同 —— 但**逐棵匹配后覆盖率高度吻合（0.613 vs 0.693）**，说明坐标系**是**一致的，差异只是"无人机只飞了测区中间一块"。

- **别只看范围不同就断言坐标系不匹配** —— 用"**匹配对上的一致性**"当判据，不要用范围
- 树数量差异（480 vs 230）常是**检测方法差异**（体素连通域法 vs CHM 峰值法），不是错误 ⇒ 先问"哪种方法"，别当 bug

## numpy 实现坑（写复算脚本必踩）

- **mask 之后必须同步 mask 所有派生数组**（老毛病，本次又撞）：
  ```
  zb 在 mask 前算 → mask 后仍直接参与运算
  ⇒ ValueError: operands could not be broadcast together with shapes (28643,) (332087,)
  判据：报错里两个形状差一个量级、且恰是\"过滤前/过滤后\"的点数 ⇒ 就是漏 mask
  ```
- **体素键打包会 int64 溢出 / 串位**（串位是静默的，更危险）：
  ```python
  # ✗ 溢出：超 int64 上限 9.2e18
  k = (vx + 1_000_000) * 4_000_000_000_000_000 + ...
  # ✗ 串位：vy+1e5 大于 stride 20000 → 相邻分量互相污染（不报错！）
  k = (vx + 100000) * 4_000_000_000 + (vy + 100000) * 20000 + (vz + 100000)
  # ✓ 8192 进制，各分量 ±4096 偏移后均 < stride
  k = (vx + 4096) * 67108864 + (vy + 4096) * 8192 + (vz + 4096)
  ```
  **自检规则**：每个分量"加偏移后的最大值"必须 **< 下一级的 stride**；最高级 × stride 必须 **< 9.2e18**。
