# 点云地面（DTM）的**验证与重建**：填充值陷阱 + 2m 列最低包络裁判

场景：拿一份真实 LiDAR 点云（LAS/PCD）做仿真地形 / 树高 / 树干覆盖度等下游用途。
**判据一条先行：先验证地面。地面错则下游全错，且症状会伪装成别的问题。**

## 一、症状 → 一定是地面错了（而不是"数据差"或"算法错"）

```
覆盖度自检报「50% 的树零树干点」    → 其实是这些树的地面被填错，树干 z 窗口挂在了错误高度
出现一批「树高 = 上限值」的假高树（被 cap 打满）→ CHM 虚高（实测 CHM 达 46~49 m）
地形 / 树高 / 树位 / 关卡物理全部带同一个偏差
```

## 二、识别"被填充过的地面场"（三步，30 秒出结论）

```python
print(np.isnan(g).sum())                              # ★ 0 就是危险信号：无数据格被填成了【有限值】
vals, cnt = np.unique(np.round(g[np.isfinite(g)], 2), return_counts=True)
print(vals[np.argsort(-cnt)][:5], cnt[np.argsort(-cnt)][:5])   # 某值占比异常高 → 那就是哨兵值
print(np.isfinite(gm).sum() / g.size)                 # 真正有数据的格占比（实测只有 25%）
```
实测记录：`ground_1m.npy` 里 **75% 的格被填成 `-8.80`**（不是 NaN ✗）→ 下游把填充值当真地面用。
**同族的另一半：`grid_max.npy` 用 `-inf` 作哨兵** ⇒ **两个数组的"无效"判据不同，别用同一套 mask** ✗。

## 三、三个"看起来对、实测没用或反而是错的"做法（都真试过）

| 做法 | 实测结果 |
|---|---|
| `median_filter(nan_to_num(ground, nan=1e6))` 后取邻域中位剔离群 | **反效果** ✗ 哨兵 `1e6` 把邻域中位整个拉高 → 算出 `-21.60` 这种明显错误的地面 |
| `grey_opening(ground, size=25)`（形态学开运算求下包络） | 可疑格 10374 → 8722（仅 −16%）✗ **伪地面区比窗口还大**，25 m 腐蚀压不下去 |
| 给地面加"高度上限"（"地面不该 >10 m"） | **前提就是错的** ✗ 见第四节 |

## 四、★★ 不要预设地面高程范围 —— 先量点云的 z 跨度（我在此自我纠错两次）

追查中我一度断定"地面 >10 m 是假尖峰"并据此压制它 ✗ **结论是错的**：
```
LAS 点云 z 范围      -27.3 ~ +46.4 m   起伏 73.7 m
修正后地面           -25.4 ~ +45.3 m   起伏 70.7 m   ✓ 吻合
树高 CHM             中位 11.8  max 26.9 m          ✓ 合理
旧 ground.npy 说地面  -24.7 ~ +7.77 m   起伏仅 32 m   ← 是它错了
```
测区本来就是**山地**。**判据：把"地面候选"的 min/max 与【原始点云的 z 范围】对比 ——
两者量级一致才可能对；再看"2m 列最低包络"的 max 能到多高，地面就能到多高。
没做这一步之前，任何"地面不该这么高"的直觉都不是证据。**

## 五、✅ 真正管用的两步

**1) 格内 z 跨度判据** —— 区分"有地面回波"与"只有树冠"的格：
```
有地面+树冠的格 → span = grid_max - grid_min 大（20~40 m）→ grid_min 就是地面 ✓
只有树冠的格   → span 小（0~3 m）→ grid_min 是树冠 ✗ 必须剔除
种子 = hasdata & (span > 3.0)，再迭代剔除"明显高于邻域"的
CHM 采样格另要要求点数够（grid_cnt >= 3），否则单点噪声会造出假峰
```

**2) ★ 2m 列最低包络 = 裁判（决定性一步）** —— 直接从原始点云算，不依赖任何中间产物：
```
每 2m 列取该列 z 的最小值 → 3x3 nanmin 抗单点 → 这就是真正的地面下包络
向量化：按 flat 索引做 stable argsort，再 np.minimum.reduceat
       （比 np.minimum.at 快几十倍；后者对 76M 点慢到不可用）
```
用它当参照逐格算误差，**立刻判出哪个地面候选更准**。三方对质实测：
```
ground.npy        误差中位 3.58   90% 14.93   最大 27.39  ✗
ground_1m.npy     误差中位 1.52   90%  7.19   最大 43.54  ✗
clean_ground_v5   误差中位 1.14   90%  2.57   最大  5.97  ✓✓  ← 最终采用
```
**最终地面** = `min(clean_ground, 2m包络最近邻铺满 + 3m)`，下界 `2m包络 − 8m`，
再 `median_filter(5)` + `gaussian(2)`；**最后把人工压平的起降坪重新写平**（平滑会抹掉它 ✗）。

## 六、连带后果与修好后的对照（说明"为什么必须先修地面再谈别的"）

```
ground 被填充值污染
  ↓ CHM = grid_max - ground 虚高（实测 46~49 m）
  ↓ 出现一批"树高 = 上限"的假高树（被 cap 打满的就是它们）
  ↓ 树干 z 窗口 [地面+0.1, 地面+min(0.4H,12)] 挂在错误高度
  ↓ 覆盖度自检报"116/230 棵树零树干点"（其实是地面错，不是没扫到）
  ↓ 关卡里这些树的高度/位置也错（按错地面放置 + 按虚高树高缩放）
```
修好地面后**同一套工具**重跑：
| 指标 | 修前 | 修后 |
|---|---|---|
| 零树干点的树 | 116 / 230 | **24 / 220** |
| 实测树棵数 | 230（含 ~77 伪峰） | **220** |
| 树高 max | 35.0（被 cap） | **26.9（无需 cap）** |
| 地面误差 中位/最大 | 1.52 / 43.54 m | **1.14 / 5.97 m** |

## 七、方法论：**先怀疑工具，别先下结论**

本次每次拿到反直觉数字（"50% 零树干点""116 棵没扫到""地面 45 m"），
**第一动作都是回头验自己的判据**，两次因此避免了错误结论（一次是哨兵污染，一次是我误判真实地形高）。抓手：
- 用**独立第二种方法交叉验证**（峰值法 vs 树干聚类法；地面候选 vs 2m 列包络）
- **逐例打印中间量**（某树周围 3 m 内点的 z 分布、径向分布），别只看汇总统计
- **自查探针脚本自己的 bug**：本次两次 `nan=1e6` 污染 → 中间结果当场作废，并**明确标注"不可用、不作为结论"**，
  绝不能拿带 bug 的中间结果当依据 ✗
